## 1. 데이터 흐름 — 팀 흐름도에 대입

```
[수집] ──▶ [정규화] ──▶ [색인]  ──▶ [사용]
 API·공공     소스 간 대조     ※ 두지 않는다    판정기 · 대안 열거
 데이터셋     + 파생 생성        (§1-3 참조)      · 근거 생성
```

### 1-1. 수집

| 소스 | 내용 | 형태 |
|---|---|---|
| 서울 열린데이터광장 OA-101 | 지하철 시간표 원본 | API |
| 국토교통부 TAGO | 지하철 보완 · 버스 | API |
| 서울 열린데이터광장 OA-15442 | 역 영문명 | 파일 |
| 국가철도공단 표준데이터 | 역 좌표 · 역 순서(FR_CODE) | 파일 |
| 서울시 버스 정보 | 노선 717 · 정류장 41,820 | API(캐시) |
| 공공데이터포털 | 공휴일 | API |

**전부 공공데이터다.** 개인정보가 들어오는 경로가 없다(§5).

### 1-2. 정규화

수집 원본을 그대로 쓰지 않는다. **소스가 서로 다른 말을 하는 자리**를 먼저 맞춘다.

- **시각을 분 단위 정수로** — 자정을 넘긴 열차를 `24:50`·`27:30` 으로 그대로 둔다(§3-1)
- **행선지(`dest_nm`)를 열차 단위로 복원** — 소스의 `SUBWAYSNAME` 은 행선지가 아니다(§3-4)
- **역명 표기 통일** — '역' 접미어 제거 · 괄호 병기 제거 · 노선명 2자리 0 패딩(`05호선`)
- **역 순서는 FR_CODE 를 정본으로** — 시간표에서 유도한 순서는 차량기지 출발 때문에 틀린다(§3-7)

### 1-3. 색인 — **두지 않는다**

**이 칸은 비어 있고, 비운 것이 결정이다.**

이동 모듈의 조회는 **「2026-09-24 평일 22:40 에 02호선 잠실에서 성수로 가는 열차가 있는가」** 다.
이건 **정확한 값 조회**이지 **의미 검색**이 아니다. 벡터 색인을 얹으면

- 같은 질문에 **매번 같은 답이 나온다는 보장이 사라지고**,
- 무엇보다 **「없다」를 「비슷한 것」으로 바꾼다.** 이 모듈이 파는 것이 정확히 그 반대다 —
  **소스가 없는 구간을 정상으로 바꾸지 않는다.**

대신 **B-tree 인덱스**(`ix_timetable_lookup`: 노선·역·요일·출발시각)로 조회한다.

> **이 결정의 절반은 잰 값이고 절반은 아직 예측이다.**
> **잰 것(2026-09-16)** — 시간표를 안 보는 경로가 「없다」를 지키는지 **ML 분류기로 실측**했다.
> 탐침 8,648건에서 근거없음 376건을 **전부(376/376) 확정답으로** 바꿨고, 회귀 85건 중 14건을 틀렸다 —
> 전부 막차·단축운행·무정차·없는 역, 시간표를 봐야 아는 자리다.
> → `2026-09-16_Mobility_ML학습결과서_v1.md`.
> **아직 예측인 것** — 벡터 검색 + LLM 판정(경로 B). **4W(9/18~9/28)에 같은 harness 로 잰다.**
> 재는 것은 **판정 일치율 · 근거 등급 정확도 · 「근거없음」을 정상으로 바꾼 건수** · 지연/비용.
> 설계: `2026-09-11_이동모듈_RAG_비교설계_v1.md`.

### 1-4. 사용

정규화 산출물을 **판정기**(`scripts/verify_time.py`)가 읽는다.
판정 경로에 **LLM 이 없다** — 코드가 시간표를 읽어 판정하고, 값마다 **근거 등급(확정/추정/근거없음) + 확인 시각**이 붙는다.

> **탐지기가 안 우는 것이 가장 위험하다.** 「이상 0건」과 「탐지기 고장」은 결과가 같다.

## 3. 찾아 고친 것 아홉 — 발견 · 원인 · 수정 · 재검증

### 3-1. 자정 넘김 미정규화

- **발견** — C4(막차 대조)에서 **첫차 불일치 757건 · 막차 652건**.
- **원인** — 소스가 00:05 열차를 `'000500'` 으로 준다. 그대로 두면 **그 열차가 그날 가장 이른 시각**이 되어
  **첫차와 막차가 둘 다 뒤집힌다.**
- **수정** — `strptime` 을 버리고 **시각을 분 단위 정수**로 다룬다(`modules/mobility/timeutil.py` 가 유일한 자).
  24를 넘긴 채로 둔다.
- **재검증** — C4 불일치 **757 → 7 · 652 → 40**.

### 3-2. 그 수정이 만든 자정 가짜 막차 — **수정이 새 버그를 만든 사례**

- **발견** — 3-1 을 고친 뒤 C1 의 판단 불가가 오히려 늘었다.
- **원인** — `'000000'` 은 시각이 아니라 **「출발 없음」**이다. +24 보정에 걸려 **24:00 가짜 막차**가 됐다.
- **수정** — `'000000'` 을 시각으로 읽지 않는다. **2,527행**이 걸러졌다.
- **재검증** — 효과가 **C4 보다 C1 에서 컸다**(판단 불가 9 → 1).
  **고친 자리와 효과가 나타난 자리가 다르다** — 한 검사만 보면 수정이 됐는지 알 수 없다.

> 이 행들은 지금도 **판정에서 제외**된다. 수집 463,326행 중 **18,411행**이 여기 해당한다(§0).

### 3-3. 검증기 자신의 표본 출력 누락

- **발견** — C4 가 통계만 찍고 **표본을 안 냈다.**
- **원인** — 검사 코드의 출력 누락. 통계가 맞으면 통과로 보였다.
- **수정** — 표본을 찍게 했다. **고치자마자 새 버그 둘이 바로 나왔다**(3-6 · 3-8).
- **재검증** — 그 전까지 **47건을 버리고 있었다.**

> **통계만 찍는 검사는 절반만 하는 것이다.**

### 3-4. 행선지 필드가 사실은 시발역 — **101개 조합이 뒤집혀 있었다**

- **발견** — 지선 편성 0편을 파다가, 같은 구간의 막차 행선지가 소스와 정반대였다.
- **원인** — OA-101 의 `SUBWAYSNAME` 은 **행선지가 아니라 시발역**이다.
  **41,510행(전체 8.9%)**, 그것도 **2호선 휴일 19,245 · 7호선 휴일 15,142** 에 몰려 있다 —
  인바운드 여행자가 주말 밤에 쓰는 바로 그 구간이다.
- **수정** — 진짜 행선지를 `TRAIN_NO` 로 열차를 복원해 얻는다(종착 행 = 출발 시각 없이 도착 시각만 있는 행).
  **37,362행(92.1%) 복원.**
- **재검증** — **2호선 막차 행선지가 101개 조합에서 바뀌었다.**
  행선지 빈 조합이 144 → 161 로 **늘었는데**, 이는 **틀린 값 17개가 「근거없음」으로 바뀐 것**이라 옳은 방향이다.
  검사 **C6**(행선지가 진행 방향의 끝에 있는가)을 신설해 회귀로 고정했다.

> **모르는 것이 늘어나는 쪽이 옳을 때가 있다.** 틀린 값을 지우면 빈칸이 는다.

### 3-5. 지선 필터가 필요한 절반을 버렸다 → 고치니 중복이 딸려 왔다

- **발견** — `신도림 → 도림천` 편성이 **0편**인데 반대 방향은 110편.
- **원인** — 수집이 아니라 **필터**였다. 남기는 기준이 *"`SUBWAYSNAME` 이 지선 역인 행만"* 이었는데,
  3-4 대로 그건 **시발역**이라 *지선에서 나오는* 열차만 남기고 *지선으로 들어가는* 열차를 버렸다.
- **수정** — 기준을 **지선 역 시간표의 `TRAIN_NO`** 로 바꿨다.
- **재검증** — 휴일은 행선지 복원만으로 살아났다(신도림 휴일 105편). 회귀 `R-MISSING-01` 이

- **추적 네 단계** — ①데이터는 있다 ②휴일 신도림 방향만 `dest_nm` null ③소스는 같다(OA-101)
  ④열차 하나(5501)의 평일·휴일 행이 **완전히 대칭**인데 평일만 복원된다 → **코드다.**
- **원인** — 행선지 복원 조건이 `len(term) == 1` 이었다. 신도림 종착 행이 **휴일만 두 파일에 중복**으로 들어와
  `len(term) == 2` → 복원 실패 → `dest_nm` null → 판정이 근거없음.
  **같은 행이 두 번 들어온 것을 코드가 「모호함」으로 읽었다.**
- **수정** — 종착 **'행'** 이 몇 개인가가 아니라 종착 **'역'** 이 하나로 정해지는가를 본다(`len(names) == 1`). **세 줄.**
- **재검증(고치기 전에 영향 범위를 쟀다)** — 복원 **37,794 → 40,056행**(+2,262행 · 487열차).
  **종착역이 실제로 둘 이상인 열차는 0개**라 느슨하게 해도 오복원 위험이 없다.
  되돌리는 조건은 **그런 열차가 나올 때**다.
- **고정** — 반대 방향 회귀 3건 신설(`R-SAT-02`·`R-SUN-02`·`R-HOL-03`, `expect_arrive` 10:11). **회귀 82 → 85건.**

**왜 6일간 못 잡았나.** 신정지선 휴일 회귀가 셋이나 있었는데 **전부 멀쩡한 까치산 방향뿐**이었다.
→ **정답표를 아무리 늘려도 안 물어본 질문은 안 나온다.**

> **자기점검이 찾고, 회귀가 지킨다.**

## 4. 중복은 세 번 모양을 바꿔 나왔다

| 회차 | 어디를 망쳤나 |
|---|---|
| ① | **적재** — 접속역을 통째로 받아 같은 열차가 두 번 들어왔다 |
| ② | **필터** — 중복을 피하려 좁혔더니 **필요한 절반을 버렸다**(3-5) |
| ③ | **복원** — 중복 두 줄을 「모호함」으로 읽고 행선지를 포기했다(3-9) |

→ **보충 수집은 반드시 중복을 만든다. 그 중복을 소비하는 쪽이 몇 군데인지 세야 한다.**
→ **중복은 모호함이 아니다. 세는 것은 행 수가 아니라 서로 다른 값의 수다.**

## 5. 개인정보 처리 — **이동 모듈은 해당 없음**

**마스킹 대상이 없다. 빈칸이 아니라 「해당 없음」이다.**

| 항목 | 이동 모듈 |
|---|---|
| 수집하는 개인정보 | **없음** — 소스가 전부 공공데이터다(§1-1) |
| 마스킹 대상 필드 | **없음** |
| 사용자 입력 | 구간·날짜·시각·동행 조건(유아/짐 여부)만 받는다. **식별자를 받지 않는다** |
| 저장하는 것 | 시간표 · 규칙 · **우리 판정 이력**뿐 |
| **저장하지 않는 것** | **경로 API 응답 — 원값도 가공값도 저장하지 않는다** |

**마지막 줄은 문서가 아니라 스키마로 강제한다.** 저장소의 `source_type` CHECK 가 `db`/`policy`/`case_event`
**3종만** 허용하고, `Evidence.value` 스키마가 `additionalProperties:false` 로 **경로·좌표·링크·외부 API 원값의 혼입을 구조로 막는다.**
그 거부가 실제로 동작하는지를 **음성 시험 12건**으로 점검한다(`tests/mobility/contract/check_fold.py`).

근거: 카카오 공식 답변(2026-09-11) — *"공공데이터의 활용 관련은 저희 운영 정책 범위에 포함되지 않습니다"* ·
**"교육·비상업 예외 구분 없음"**. → **"교육용이라 괜찮다"를 근거로 쓰지 않는다.**

## 8. 이 전처리에서 배운 것 — 다음 데이터에도 그대로 쓴다

1. **소스별 검사로는 안 나오고 소스 간 대조로만 나오는 버그가 있다.** 아홉 중 일곱이 그랬다.
2. **수정은 새 버그를 만든다.** 3-1 의 수정이 3-2 를 만들었고, 3-6 의 필터가 시발 열차를 죽였다.
   **고칠 때마다 검사 묶음 전체를 다시 돌린다.**
3. **고친 자리와 효과가 나타나는 자리는 다르다.** 3-2 는 C4 를 고치려고 했는데 C1 에서 효과가 났다.
4. **모르는 것이 늘어나는 쪽이 옳을 때가 있다.** 틀린 값 17개가 근거없음으로 바뀌었다(3-4).
5. **통계만 찍는 검사는 절반만 한다.** 표본을 찍게 하자 버그 둘이 바로 나왔다(3-3).
6. **정답표를 아무리 늘려도 안 물어본 질문은 안 나온다.** 회귀 82건이 6일간 못 잡았다(3-9).
7. **중복은 모호함이 아니다.** 세는 것은 행 수가 아니라 서로 다른 값의 수다(§4).
8. **문서에 적힌 방법이라도 데이터로 확인한다.**(3-7)
9. **탐지기가 안 우는 것이 가장 위험하다.** 그래서 탐지기 자체를 10건으로 점검한다.
10. **시간표를 안 보는 경로는 「없다」를 못 지킨다.** 분류기로 실측했다 — 376/376(학습결과서).
