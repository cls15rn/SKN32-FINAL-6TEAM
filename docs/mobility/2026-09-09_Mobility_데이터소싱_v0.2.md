# Mobility(이동·동선) 모듈 데이터 소싱 v0.2

작성일: 2026년 9월 9일 (v0.1 같은 날 오전) · 담당: 서유현

Mobility 모듈이 판정에 쓰는 데이터를 소스별로 정리한 문서다. 무엇을 어느 단계에서 쓰는지, 저장해도 되는지, 코어 계약의 `Evidence`에 어떻게 실리는지를 적는다. 확보 상태는 2026-09-09 기준이고, 수치 중 근거가 없는 것은 [추정]으로 표시했다. 설계서 v0.2 8절의 표를 이 문서가 대신하며, 설계서는 이 문서를 참조한다. v0.2에서 바뀐 것: 미확보 5개 중 4개(공항 리무진·버스·역 좌표·운행 장애)의 소스를 확정하고 수집 스크립트를 붙였다.

## 1 원칙

- **저장은 시간표·규칙 표·우리 판정 이력뿐이다.** 경로 API 응답은 처리 중 메모리에서만 쓰고 저장·캐시하지 않는다(카카오 약관).
- **저장하는 행에는 수집 시각과 소스 이름이 반드시 붙는다.** 코어 `Evidence`가 `source_type · source_id · observed_at`을 의무로 요구하고, 시간표 근거의 `observed_at`은 판정 시각이 아니라 **그 시간표를 받은 시각**이어야 하기 때문이다.
- **성립 여부는 시간표로 끝내고, 외부 호출은 경로 모양이 필요할 때만 한다.** 쿼터·비용·약관 위험을 같이 줄인다.
- 시간표대로 오는 차는 없으므로 시간표는 "기록"으로만 확정이다. 소요·도착 시각은 항상 추정이고 버퍼가 오차를 흡수한다.

## 3 소스별 상세

### 3-1 지하철 시간표 — 수집 완료 (TAGO + 열린데이터광장 보충)

**결과(2026-09-09).** 역 ID 819개, 조합 4,914개, 통합 시간표 **465,490행**. 서울 1~9호선 커버리지 **100%**(4호선 신길온천 1역 제외), 공항철도·인천1·2호선·서해선·GTX-A·신분당·김포·신림·용인·우이신설·의정부·경강도 100%. 남은 "근거 없음"은 경춘선 24역, 경의선 4역(금릉·금촌·일산·파주), 수인분당 5역(미금·보정·야탑·죽전·신길온천)으로 **전부 서울 밖**이라 MVP 범위(서울 1도시)는 닫혔다.

| 소스 | 행 | 비고 |
|---|---|---|
| TAGO `1613000/SubwayInfo` | 424,170 | 주 소스. 10,000/일 |
| 서울 열린데이터광장 `SearchSTNTimeTableByIDService` | 41,510 | TAGO에 없는 곳 보충 — 2·7호선 휴일 전체 + 빈 곳 19건(2호선 평일 11역, 종로3가, 응암, 청량리 등) |

**응답 특징.** `depTime`은 `HHMMSS` 또는 `'0'`(시·종착). 검색 응답의 역명 키는 `subwayStationName`, 시간표 응답은 `subwayStationNm`으로 다르다. 요일 코드는 01 평일 / 02 토요일 / 03 휴일인데 **수도권은 02가 비어 있고 토·일·공휴일을 03으로 준다**(우이신설만 02 별도) — 판정기는 토요일을 holiday로 본다 [추정 — 운영사 공식 시간표가 평일/토·공휴일 2종인 것과 일치].

**역명 매칭에서 배운 것 — 버스·정류장 데이터에도 그대로 나올 문제다.**

| 함정 | 증상 | 보정 |
|---|---|---|
| **괄호 병기** | TAGO는 "경복궁(정부서울청사)", "잠실(송파구청)", "이촌(국립중앙박물관)"으로 부른다. 정확 일치로 거르면 655개 중 79개가 통째로 누락 | 괄호 앞·괄호 안 일치 규칙 |
| **'역' 접미사** | "하남검단산역", "김포공항역"(서해선) | 접미사 규칙 |
| **동명 역의 도시 구분** | 노선명이 "1호선"처럼 도시 없이 온다. "교대"·"증산"·"죽전"은 부산·대구 역이 정확히 일치해 **서울 역을 가렸다** | 매칭 전에 운영사 ID 접두어(MTRBS/MTRDG/MTRDJ/MTRGJ)와 부산 동해선을 제외 |
| **환승역이 노선별로 따로 잡힘** | "이촌"은 경의중앙선에 정확히 일치해 매칭이 거기서 끝나고 4호선을 못 찾는다. 이런 역이 12개(종로3가 5호선, 김포공항 서해선, 청량리 1호선 …) | 첫 규칙에서 멈추지 않고 **모든 규칙의 합집합**. 열린데이터광장 기준 소속 노선과 대조해 부족하면 재검색 |
| **검색어가 0건** | "4·19민주묘지"는 가운뎃점 때문에 검색이 안 된다 | 문장부호 변형·한글 부분 검색으로 넓힘 |
| **빈 조합의 원인 구분** | 조합 1,902개가 비었는데 수집 실패인지 소스에 없는지 알 수 없었다 | 재시도해 응답 상태를 기록. 354개 전부 "진짜 없음"으로 확인(6호선 응암순환 상행이 없는 것은 실제 운행 구조와 일치) |

**저장.** 행마다 `fetched_at`(수집일, precision=day)·`source`를 붙인다. `Evidence(source_type="db", source_id="tago_subway@2026-09-09" 또는 "seoul_opendata_OA-101@…", observed_at=수집일)`로 판정에 붙는다.

**스크립트.** `tago_subway_collect.py`(수집·체크포인트) → `tago_fix_unmatched.py`(역명 보정, 보정표 `tago_name_map.json`) → `tago_retry_empty.py`(빈 조합 원인 구분) → `seoul_fill_gaps.py`(서울 1~9호선 구멍을 열린데이터광장으로) → `build_timetable_v1.py`(통합·커버리지). 갱신은 시간표 개정(분기~반기) 단위로 재수집.

### 3-2 서울 열린데이터광장 — 역 참조 데이터와 교차검증

역 목록(OA-15442)은 역코드·외부코드·영문/중문/일문 역명을 가져 링크의 장소명(영문 출력)과 노선 매핑에 쓴다. 첫차막차(OA-15492)는 2·3·5~9호선만 있어 판정 근거로 쓰지 않고, TAGO 시간표에서 뽑은 첫차·막차와 대조하는 검증용이다. 시간표(OA-101)는 TAGO가 전 노선을 덮으므로 수집하지 않는다.

### 3-3 카카오 경로 — 호출만, 저장 없음

- 대중교통·도보 경로 REST 각 1,000/일. 출발 시각을 지정할 수 없으므로 "그 시각에 성립하는가"는 카카오가 아니라 시간표가 답한다. 카카오는 **경로 모양**(어느 노선·환승 몇 번·도보 몇 m·대략 몇 분)만 준다.
- 호출 지점 3곳: 최초 검증(구간당 1회), 수정·사건(영향 구간 × 후보), 재확인에서 경로가 바뀌어야 할 때. 여행당 30~60회 [추정].
- 저장 금지 → `Evidence.value`에는 응답 원값이 아니라 판정에 필요한 **파생값**만 넣는다: 성립 여부, 이용 노선명, 환승 횟수, 도보 거리 구간(예: "500~800m"), 추정 소요 5분 단위, 도착 추정 구간. 정류장 목록·경로 좌표·요금·소요 원값은 넣지 않는다. 카카오맵 링크는 우리가 장소명+좌표로 조립하므로 호출이 없다.
- 호출 실패 시: 시간표만으로 성립 여부는 내고 소요·환승은 "판단 불가"로 표시한다. 정상으로 바꾸지 않는다.

### 3-4 규칙 표 — `policy` 근거

`config/mobility/rules_v0.2.json` — 값마다 `grade`(확정/추정)와 `근거`가 붙어 있고 `rules_check.py`가 검사한다. `Evidence(source_type="policy", source_id="mobility_rules@v0.1", observed_at=개정일)`로 판정에 붙는다.

담는 것: 초행 길찾기 환승당 1분, 대형 환승역 통로 가산 2분, 환승 대기 모델(배차의 절반, 막차 근처·진행 중은 배차 전부), 정책 버퍼 10분(진행 중 15분), 상한(환승 2회·유아 1회, 도보 1200m·유아·짐 800m), 버스 대기 모델, 시간표 노후 경고 30일, 후보 열거 순서.

**환승 고정 여유는 0이다.** 카카오 `totalTime`에 환승 도보가 이미 들어 있어 더하면 이중 계산이다(팀 피드백 9/9). **그리고 MVP는 카카오 도보 시간을 그대로 쓴다** — 실측 기준선 1.04 m/s가 성인 평균보다 25% 느려 보통 일행엔 여유가 있고, 보정 계수는 전부 [추정]이라 판정 오류의 원인을 가리기 어렵다. 계수는 동행 조건이 넘어오는 확장 단계로 미루고 값·근거만 규칙 파일에 남겼다. 도보 10분 초과 + 느린 동행 조건이면 `warnings`로 표시한다.

**반대로 `totalTime`에 대기 시간은 아예 없다**(2026-09-09 실측 — 총 시간이 step 시간의 합과 일치하고 잔여 구간의 함의 속도가 도보와 같다). 차를 기다리는 시간을 우리가 시간표로 채우는 것은 이중 계산이 아니라 빈 자리를 메우는 것이다. 보행 기준선만 [확정]이고 나머지 값은 [추정]이라 합성 여행 20~30건으로 조정한다.

### 3-5 공항 리무진 — 인천공항 버스정보 (확정)

### 3-6 시내버스 — 서울은 TAGO에 없고 자체 API를 쓴다 (2026-09-09 확인)

- **TAGO 버스노선정보의 도시코드 138개에 서울특별시가 없다**(`probe_tago_bus.py`). 서울시는 자체 API를 운영해 전국 API에서 빠진다.
- TAGO로 되는 곳: 인천 382개 노선, 수원 104개 등. `getRouteNoList`가 첫차·막차를, `getRouteInfoIem`이 배차간격을 준다. 수집은 `tago_bus_route_collect.py --city 23`(도시코드는 `--list-cities`).
- **서울**: data.go.kr 15000193(`서울특별시_노선정보조회`) 활용신청 → `ws.bus.go.kr` 호출. 2단계다 — `getBusRouteList?strSrch=721`로 `busRouteId`를 찾고 `getRouteInfo?busRouteId=…`로 상세를 받는다. TAGO 지하철에서 쓴 흐름과 같다.
  - 응답의 **`term`이 배차간격(분)**, `firstBusTm`·`lastBusTm`이 첫차·막차, `stStationNm`·`edStationNm`·`corpNm`도 온다.
  - 서울 열린데이터광장은 신규 인증키 발급에 제한 안내가 있으나, data.go.kr 발급 키로 같은 엔드포인트를 부르는 경로라 별개일 수 있다 — 승인 후 확인.
- **판정 방식이 지하철과 다르다.** 지하철·공항 리무진은 출발 시각 목록이 있어 "그 시각에 차가 있는가"를 직접 본다. 시내버스는 노선 단위라 "운행 구간 안인가 + 배차만큼 대기"로 본다. **첫차·막차는 확정, 대기는 추정**이다.
- **`term`의 한계**: 노선당 값 하나라 시간대별 차이를 담지 못한다. 출퇴근 8분·심야 20분인 노선도 `term=8`로 온다. 판정이 가장 아픈 막차 근처가 곧 배차가 벌어지는 시간대이므로, 규칙의 `worst_case: headway_full`(막차 근처·진행 중은 배차 전부를 대기로)을 유지한다.
- **실시간 위치로 실제 배차를 계산하는 것은 범위 밖**이다. 우리는 미래 시각을 판정하는데 실시간 위치는 현재만 말한다. 시간대별 분포를 만들려면 며칠치 관측이 필요하고 7주 일정에 맞지 않는다 → 확장 항목.
- MVP 우선순위: 서울 지하철 100%, 공항 리무진 확보이므로 시내버스는 지하철이 닿지 않는 구간(남산·북촌 일부)용 2순위. 확보 전까지 그 구간은 "근거 없음".

### 3-8 운행 이슈 — **코어 담당으로 이관 (2026-09-09 합의)**

사고·화재·무정차·통제 같은 운행 이슈는 **코어단이 확인**하고, Mobility는 `current_state.replan` 또는 `input_text`로 조건만 받아 재판정한다. 이유: 이슈는 이동만의 문제가 아니라 액티비티·예약에도 동시에 걸리고, 한 소스를 모듈마다 각자 폴링하면 판정 시각이 갈린다(타이머를 모듈 밖에 둔 것과 같은 이유).

여기서 조사한 소스는 버리지 않고 **§3-11에 코어 인계 자료로 옮겼다.** Mobility 쪽 남는 일은 하나 — 이슈가 들어왔을 때 해당 노선을 제외하고 대안을 열거하는 판정 경로이며, 이건 재계획(F3)에서 이미 만든다.

## 5 담당 결정과 이유

| 결정 | 이유 |
|---|---|
| 시간표 단일 소스 = TAGO | 열린데이터광장은 1·4호선·공항철도가 없다. 인바운드 여행의 양 끝(공항철도·1호선 서울역)이 빠지면 가장 중요한 구간이 "근거 없음"이 된다. 열린데이터광장은 역 참조·교차검증으로만 남긴다 |
| `fetched_at`은 수집일 정밀도 | v1 수집 스크립트가 행 단위 호출 시각을 남기지 않았다. 시간표 개정은 일 단위보다 훨씬 드물어 판정 근거로 충분하고, `precision=day`를 함께 적어 정직하게 표시한다. 재시도·보정 수집분은 행 단위 시각을 남긴다 |
| 토요일 = 휴일 시간표 | TAGO 수도권 02가 비어 있고 운영사 공식 시간표가 평일/토·공휴일 2종. 별도 토요일 시간표가 확인되면 그때 분리 |
| 2·7호선 휴일은 열린데이터광장으로 보충 | TAGO에 없다. 같은 통합 스키마에 `source`만 다르게 실어 판정기는 소스를 구분하지 않고 Evidence.source_id만 달라진다 |
| 수도권 밖 운영사 행 제외 | 서울 1도시 범위. 동명 역이 섞이면 막차 판정이 다른 도시 시간표로 나갈 수 있다 |
| 카카오 근거는 파생값만 | 약관(응답 저장·캐시 금지)과 에이전트가 제3자인지 회색이다. 판정에 필요한 요약값은 우리 판정의 일부이고, 원값은 남기지 않는다 |
| 시간표 30일 초과 시 warning | "확인 시각"이 오래된 근거로 확정을 말하지 않기 위해. 재수집 트리거이지 판정 불가는 아니다 |
| 버스 판정은 구간+배차, 값은 추정 | 버스 소스는 열차 단위가 아니라 노선 단위(첫차·막차·배차간격)다. 첫차~막차 구간 안인지는 확정, 대기 시간은 배차 평균이라 추정. 지하철과 같은 확정도로 말하지 않는다 |
| 역 좌표는 저장 가능한 공공데이터로 | 카카오 좌표는 저장 금지라 시간표 옆에 둘 수 없다. 링크 조립은 매 판정에 좌표가 필요하므로 저장 자유·연 1회 갱신인 국가철도공단 표준데이터를 쓴다. 수동 다운로드 1회는 그 대가로 받아들인다 |
| 운행 이슈 소스는 코어에 넘긴다 | 팀 합의(9/9). 이슈는 여러 모듈에 동시에 걸리는 공통 입력이고, 모듈마다 폴링하면 같은 사건을 다른 시각으로 본다. 조사 결과는 버리지 않고 §3-11에 인계 자료로 남긴다. Mobility는 이슈 조건을 받아 재판정하는 쪽만 책임진다 |
| 소스가 없는 구간은 "근거 없음" | 소스가 없는 구간을 정상으로 바꾸지 않는다는 원칙. 근거 없음 반환이 시연에서도 정직성 장면이 된다 |
