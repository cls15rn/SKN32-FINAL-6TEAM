## TMAP: 문서에서 확인한 범위와 미확인 영역

- 대중교통 요청의 `searchDttm`은 **설정 시각의 이동수단 운행 여부**를 확인하는 기능이라고 명시돼 있다. 응답 `service`는 운행중/운행종료 구분이다. 날짜 형식이 허용된다고 그 날짜 시간표·정확한 환승 연결까지 지원한다는 뜻은 아니다. 현재 명세의 `sectionTime`·`totalTime`을 절대 승하차 시각으로 해석하지 않는다. [공식 명세](https://transit.tmapmobility.com/docs/routes)
- 대중교통 경로에 전체 도보 경로, 거리·시간·환승 횟수·정류장 정보가 있다. 도보 단독도 별도 API가 있다. [도보 명세](https://tmap-skopenapi.readme.io/reference/보행자-경로안내)
- 일반 API와 대중교통 API에 **저장 후 24시간 이상 사용 불가** 조항이 있다. 이는 장기 이력·가공 판정·제삼자 전달을 포괄 허용하는 문구가 아니다. 이번에는 응답을 파일에 남기지 않는 테스트만 준비했다. [대중교통 약관](https://transit.tmapmobility.com/terms), [일반 API 약관](https://tmapapi.tmapmobility.com/terms.html)
- 24시간이 지난 데이터를 새로 조회했다고 이전 응답의 이용기간이 연장되는 것은 아니다. 7일 여행 이력을 보관하는 구조의 해법으로 아직 확정하지 않는다. 위 조항만으로 가공한 불리언의 장기 저장이나 외부 LLM 전달을 승인하지 않는다.
- 주 프로젝트 `.env`의 변수 이름만 검사했으며 TMAP용 키를 찾지 못했다. 키 값은 출력하지 않았다. 다른 파일명·변수명에 키가 있다면 경로/이름 확인이 필요하다. 실 API 호출 수: **0회**.

테스트 준비: [probe_tmap_routes.py](../../scripts/probe_tmap_routes.py). 낮/심야 두 구간, 주말, 공항의 대중교통 6건 + 도보 2건. 기본 실행은 네트워크 없는 dry-run이며 8개 요청 구성 확인 완료. `--live`에서만 호출한다. HTTP 200만으로 경로 확보 성공으로 처리하지 않고 경로 유무·운행 flag·도보 geometry를 확인한다. 차량·타임머신 자동차는 이 1차 테스트에 아직 포함하지 않았다.

키 설정 방법: [공식 이용절차](https://transit.tmapmobility.com/guide/procedure)에서 대중교통 API 사용 등록 및 앱 키 발급. 일반 TMAP API 권한도 별도 확인. `.env`의 `TMAP_APP_KEY` 사용, 대중교통 키가 별도이면 `TMAP_TRANSIT_APP_KEY`로 구분한다. 키는 저장소/채팅에 공유하지 않는다.

- 독립 보행 2건은 경로 형상과 총 시간·거리 필드를 반환했다. 현장 통행 가능성과 접근성은 미검증이다.
- 키와 원본 응답은 파일에 저장하지 않았다. 테스트 요청과 기능 존재 여부만 출력했다.

## 다음 단계

1. TMAP 키와 서비스 권한 확보 후 준비된 8건을 실호출해 운행 flag·시각 의존성·도보 반환을 확인한다. 필드 존재와 운행 정확도를 구분한다.
2. TMAP에 절대 승하차 시각이 없다면 자체 시간표를 연결하는 방식의 데이터 대응을 검증한다. 노선 ID를 이름 유사도만으로 연결하지 않는다.
3. 자체 라우팅은 최신 버스 경유정류장·운행정보, 운행 회차 연결, 환승 시간·역 출입구를 확보해야 한다. KTDB는 구조 실험 후보이며 현재 여행의 정답 데이터로 쓰지 않는다.
4. 장기 판정 이력과 외부 에이전트 전달이 미확정인 상태에서 제공자 전환·코어 저장 경로 수정은 하지 않는다. 현재 테스트 스크립트와 검토서만 추가했다.
