## 3. ★ 행수 불일치 — 정직하게 적는다

`mobility.sqlite`(9/13 적재)와 DDL 주석·대조 질의(§E)는 **버스 21노선 · 1,397행** 기준이다.
9/14 전수 확장으로 processed 파일은 **717노선 · 41,820행**이 됐고 **재적재는 아직 안 했다.**
→ 설계 문서에는 **717 / 41,820** 으로 적고, "재적재 후 `load_mobility_db.py --verify-only` 로 대조" 를 남은 작업으로 표기.

## 4. 반드시 지킬 것 (설계 문서 "제약" 절에 그대로)

- 시각 컬럼을 `TIME` 으로 잡지 않는다 — 분 단위 integer, 24시 이상 허용
- `dep_min` NULL 허용 — 0 이면 막차가 뒤집히고 24 면 가짜 막차가 생긴다(2,527행)
- 방향의 정본은 `dir` 이 아니라 행선지(`dest_station_nm`) + `mob_line_edge`
- 시발역(`orig_station_nm`)과 행선지는 **다른 컬럼**
- 카카오 유래 값은 **컬럼으로 만들지 않는다**
- `source_type` CHECK 3종 · `mob_leg_verdict` 는 참조 표에 FK 없음(일부러)
