# 이동 모듈 — 이렇게 부르면 됩니다 (v2 · 2026-09-25)

> v2(같은 날): `options[]` 에 후보가 여럿 실리고, 칸 두 개(`walk_m`·`fare_krw` — 둘 다 route_def 의 기존 칸)와 수단 태그(id 앞머리)·이유(label 뒤)가 붙었습니다. 부르는 법은 v1 과 같습니다.

이동 모듈은 **일정(places·items)을 받아 이동 항목과 경로 정의를 채워** 돌려줍니다.
입력·출력 모두 `CreateTrip` 의 **기존 칸**입니다. 새 필드는 없습니다(출력 스펙 v1.3).

## 1. 부르는 법

**함수**
```python
from app.modules.travel_ops.mobility.engine.plan import plan

out = plan(body["places"], body["items"], body.get("party_size"), body.get("constraints"),
           routes=body.get("routes"))          # 기존 routes 키는 새 키로 안 씁니다
body["items"] = out["items"]
body["routes"] = {**body.get("routes", {}), **out["routes"]}   # 덮어쓰지 말고 합쳐 주세요
```

**CLI** (저장소 루트 · `$env:PYTHONPATH = "final_project_cs"`)
```
python -m app.modules.travel_ops.mobility.engine.plan --in trip_in.json --out trip_out.json
```

- 예시: `tests/mobility/plan_example_in_v1.json` → `plan_example_out_v1.json`(지하철·도보) · `plan_example_out_all_v1.json`(버스 포함)
- 처음 한 번 시간표를 올립니다(프로세스당 한 번 · 수 초~수십 초). `.env` 의 `DATA_DIR` 에 시간표가 있어야 합니다.

## 2. 넣는 것 (전부 기존 칸)

| 칸 | 쓰는 곳 |
|---|---|
| `places[]` 의 `key`·`name`·`lat`·`lon` | 출발지·도착지 |
| `items[]` 의 `place`·`starts_at`·`ends_at`·`kind` | 다음 항목 `starts_at` = 도착해야 할 시각 · 앞 항목 `ends_at` = 떠날 수 있는 가장 이른 시각 |
| `party_size` | 그대로 받습니다(지금 판정에는 안 씁니다) |
| `constraints.first_visit` | 초행이면 환승마다 길찾기 1분을 더합니다(없으면 초행으로 봅니다) |
| `constraints.mobility_ease == "needs_rest"` | 환승 상한을 1회로 줄입니다 |

## 3. 받는 것

| 칸 | 값 |
|---|---|
| `items[]` | 받은 항목 사이에 **이동 항목(`kind: "mobility"`)을 끼운 전체 목록**. `seq` 는 1부터 다시 매깁니다. 다른 칸은 손대지 않습니다 |
| 이동 항목 `starts_at` | **출발 시각** — 이때 떠나면 여유를 두고 다음 일정에 닿습니다 |
| 이동 항목 `ends_at` | 도착 예정 = `starts_at + eta_min` |
| `routes{키}` | `from` · `to` · `planned` · `options[{id, label, eta_min, walk_m?, fare_krw?, uses}]` |
| `options[].id` | 앞머리가 수단입니다 — `subway_1` · `bus_7022`(버스는 노선번호) · `walk` · `bike` |
| `options[].label` | 경로 + 이유. 예 `3호선 경복궁→을지로3가 → 2호선 을지로3가→성수 — 소요 가장 짧음` (이유는 실린 후보끼리 비교한 사실이고 순위가 아닙니다) |
| `options[].eta_min` | 걸리는 시간(분 · 중앙값 · **여유 안 섞음**) |
| `options[].walk_m` | 경로 안 도보 합(m). 모르는 구간이 있으면 칸이 없습니다 |
| `options[].fare_krw` | 1인 요금 — 지금은 **도보(0원)·자전거만** 냅니다. 지하철·버스는 요금 근거를 아직 안 갖춰 칸이 없습니다(그래서 재계획 대안 비교에서는 요금 미상으로 빠집니다) |
| `options[].uses` | 합의한 표기(`2호선:을지로3가` · `버스:2224`) — 내보내기 전에 `route_uses.problem()` 으로 스스로 검사합니다 |

- 이동 항목의 끝(`ends_at`)과 다음 일정 시작 사이에 남는 시간이 **여유**입니다. 여유 분은 따로 보내지 않습니다.
- 시각은 항상 `+09:00`. 새벽 4시 전 시각은 전날 운행의 연장으로 계산합니다(00:30 도착 = 전날 막차 기준).
- `options` 는 순위가 없습니다. `planned` 는 **가장 늦게 떠나도 되는 후보**입니다.
- `options` 에는 **그 이동 항목의 `starts_at` 에 떠나도 제때 닿는 후보만** 들어 있습니다. 옵션을 바꿔도 출발 시각은 그대로 써도 됩니다(더 일찍 떠나야 하는 후보는 싣지 않습니다 — 후보마다 출발 시각을 따로 두는 칸이 없어서입니다).
- 그래서 후보가 하나뿐인 구간이 많습니다. 뺀 후보와 이유는 봉투의 `left_out` 에 있습니다(몸통에 옮기지 않습니다).
  `earlier_departure`(이동 출발에서 판정기로 다시 봐도 안 됨 · 더 이른 역산 출발은 성립 확인) · `not_confirmed`(그 출발에서 확인 안 됨) · `before_prev_end`(앞 일정과 겹침) · `uses_format`(표기 검사 불통과) · `bus_cap`·`bus_more`(버스 직행 상한 밖)
- 표시 전용 필드(`transfer_car` 등)는 기본으로 안 나옵니다. 켜서 뽑은 결과를 등록에 쓰려면 **이번에 받은 routes 에만** `core_routes()` 를 쓰고 그다음 기존 routes 와 합쳐 주세요 — `body["routes"] = {**body.get("routes", {}), **core_routes(out["routes"])}`. 합친 뒤에 쓰면 기존 옵션의 `eta_min_if_controlled`·`walk_note` 같은 칸까지 지워집니다.

## 4. 못 채운 구간

값을 모르면 **이동 항목을 만들지 않습니다**(지어내지 않습니다). 그 구간은 봉투의 `skipped` 에 이유가 있습니다.

| code | 뜻 |
|---|---|
| `no_data` | 좌표가 없거나 · 걸어갈 거리 안에 역이 없거나 · 시간표가 없음 |
| `arrive_late` | 앞 일정이 끝난 뒤 떠나서는 다음 일정에 못 맞춤 |
| `before_first` · `after_last` 등 | 첫차 전 · 막차 뒤 |

- 받은 일정에 이미 이동 항목이 있었고 우리가 그 구간을 못 채우면, **받은 이동 항목을 그대로 둡니다**. 첫 일정보다 앞선 이동(공항 → 호텔 등)도 그대로 둡니다.
- 앞 일정이 초 단위로 끝나면(09:47:30) 출발은 다음 분(09:48)부터 잡습니다.
- 장소가 없는 항목(자유 시간 등)을 사이에 두면 그 앞뒤는 잇지 않습니다(어디서 떠나는지 모름).
- 봉투의 `skipped`·`left_out`·`basis` 는 `CreateTrip` 칸이 아닙니다 — **`items`·`routes` 만 옮겨 주세요**(`extra="forbid"`).
