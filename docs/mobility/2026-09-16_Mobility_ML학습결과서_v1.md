## 1. 무엇을 실험했나 — 질문 하나

**「시간표를 안 보고, 입력 특징만으로 판정을 배울 수 있는가.」**

배울 수 있으면 시간표 463,326행과 판정 코드가 필요 없다. 못 배우면 "판정은 코드"가 숫자로 선다.
어느 쪽이든 결론이 선다 — 그래서 돌렸다. *예측을 확인 없이 문서에 쓰지 않는다*가 이 모듈의 규칙이다.

| | A · 현행 | C · ML |
|---|---|---|
| 근거 찾기 | 시간표 조회(노선·역·요일·출발시각 인덱스) | **조회 없음** |
| 판정 | 규칙 코드 (`scripts/verify_time.py`) | 3클래스 분류 — 성립 / 불가 / 근거없음 |
| 입력 | 구간·날짜·출발시각·동행 조건 | 같은 입력에서 뽑은 특징 27개 (§2) |
| 출력 | 판정 + 근거 등급 + 확인 시각 + 도착·여유·완화·대안 | **판정만** |

**비교 축 셋 (`2026-09-16_Mobility_ML비교_별도프로젝트_인계_v1.md` §1 의 규칙)**

1. A 가 이미 숫자를 내는 자리에만 넣었다 — 판정 3클래스. 기준선이 없는 자리(실측 소요시간)에는 넣지 않았다.
2. 출력 스키마를 A 와 같게 강제했다 — C 는 근거 등급을 못 내므로 그 칸은 **"측정 불가(구조)"** 로 적는다.
3. 정답 없이도 재는 지표를 썼다 — 판단불가 재현율 · **근거없음→성립 전환 건수** · INV-FLIP 위반 · 지연.

## 2. 데이터와 학습 조건

### 2-1. 학습 데이터 — 자기점검 탐침 8,648건

`selfcheck_mobility.py` 와 같은 씨앗(회귀 케이스 5파일)·같은 간격(30분)·같은 대표일(평일·토·일·공휴일)로 만든다.
**구간 23종 × 왕복 × 요일 4종 × 47시각 = 8,648.** 라벨은 **A 가 낸 판정**이다.

| 라벨 | 건수 | 비율 |
|---|---|---|
| 성립 (feasible) | 5,860 | 67.8% |
| 불가 (infeasible · 탈락 포함) | 2,412 | 27.9% |
| 근거없음 (unknown) | 376 | **4.35%** |

**근거없음 376건은 전부 한 구간이다** — 일부러 없는 노선(버스 9999, 케이스 `BUS-06`).
그래서 구간 단위로 나누면 **근거없음 구간은 항상 시험 쪽에만 있다.** 이게 불공평이 아니라 **실제 상황**이다 —
운영에서 만나는 데이터 구멍은 학습 때 본 적 없는 구멍이다.

### 2-2. 특징 27개 — 시간표 누수 없음

시각(`depart_min` · sin/cos · 자정 넘김) · 요일(`day_type` · 토요일) · 구간 구조(`n_legs` · `n_bus` · `n_disrupt` · 동행 인원) ·
노선 원핫(1~9호선) · 좌표(출발·도착 위경도 · 구간 거리 합 · 직선 거리 · 좌표 결측 수).

**시간표 · 도착 시각 · A 의 출력은 특징에 넣지 않았다.** 넣으면 A 를 베끼는 실험이 된다.

### 2-3. 분할 — 구간(route) 단위 GroupKFold 5폴드 × 시드 5회

같은 구간이 학습·시험에 같이 들어가면 **외우기 시험**이 된다. 구간 단위로 잘랐다.
대조군으로 **구간을 섞어 나눈 것(외우기 허용)** 도 같이 돌렸다 — 두 표의 차이가 **외운 것의 크기**다.

### 2-4. 모델 셋 — 작은 것부터

| 모델 | 무엇 | 왜 |
|---|---|---|
| `logreg` | 로지스틱 회귀 | 선형으로 되는지 |
| `hgb` | HistGradientBoosting (300 iter) | 표 데이터 표준 |
| `mlp` | MLP 64-32 (작은 DL) | 딥러닝 산출물 요구에 대한 최소 응답. GBM 이 지는 걸 확인한 뒤에만 키운다 |

sklearn 1.8 · 학습 시간 각 0.1 / 1.6 / 1.2초. **계산이 아니라 설계가 비용이다.**

## 4. 결정 — 판정 경로에 ML 을 넣지 않는다

- **정한 것**: 판정은 코드+시간표 그대로. 이 실험 결과를 그 결정의 근거로 제출한다.
- **대신 버린 것**: ① 정확도를 올리려 특징에 시간표 파생값을 넣는 것(그러면 A 를 베끼는 것이다) ② "해당 없음"으로 내는 것(안 해 보고 적으면 발표에서 한 번에 무너진다).
- **왜(숫자로)**: 근거없음→확정답 **376/376**. 원칙 하나가 통째로 깨진다. 회귀 **71/85** 의 14건이 전부 우리가 파는 자리다. 근거 등급이 **구조적으로 없다**.
- **되돌리는 조건**: 「모른다」를 낼 수 있는 구조(예: 시간표 조회 결과를 입력으로 받는 2단 모델)가 생기고, 그 구조로 회귀 85/85 + 근거없음→성립 0 을 지키면서 A 가 못 하는 것을 하나라도 더 할 때.
- **확인 안 한 것**: §5.

**ML 이 들어갈 수 있는 자리는 판정이 아니라 추정이다** — 시간표가 없는 버스 구간의 소요시간(§6).

## 5. 확인 안 한 것 · 한계 — 물으면 "확인 안 했다"고 답한다

- **라벨이 A 의 출력이다.** 이 실험은 "규칙을 모델이 다시 배울 수 있나"를 잰 것이지 A 보다 나은 정답을 찾은 게 아니다. A 가 틀린 곳은 C 도 같이 틀린다. 사람이 박은 기대값은 회귀 85건뿐이다.
- **구간 23종은 적다.** 지하철 17 · 버스 6. 폴드 편차 ±0.12 가 그 결과다. 구간을 늘리면 숫자가 움직인다 — **모집단을 항상 같이 적는다.**
- **근거없음이 한 구간(9999)뿐이다.** 근거없음 재현율 0.000 은 "구멍이 하나라서" 나온 값이기도 하다. 구멍을 여럿 만들어 다시 재면 0 이 아닐 수 있다 — 단 그래도 §3-2 처럼 확정답으로 바꾸는 건수는 0 이 안 된다.
- **하이퍼파라미터를 안 찾았다.** 기본값에 가깝다. 찾으면 정확도는 오르지만 §3-4 의 구조 칸은 안 바뀐다.
- **DL 은 MLP 64-32 하나다.** 더 큰 망은 GBM 이 지는 걸 확인한 뒤에만 — 이번엔 GBM 이 이겼다.
- **지연 비교는 같은 실행 안의 상대값이다.** C 예측 0.02ms/건 · A 11.5ms/건(이 실행). 절대값은 인용하지 않는다 — 기기마다 다르다.

### 5-1. 위 한계 셋을 실험으로 되물었다 — v2 (EXP-08 ~ 11) · 결론 유지

| A 현행 | 1.000 | — | 1.000 | 0 | 0 | 85 |

**읽는 법**
- 근거없음 재현율 0 → 0.70. §5 세 번째 줄이 맞았다 — "구멍이 하나라서" 0 이었다. 구멍을 아홉 개 주니 「모른다」를 배우기는 한다.
- 그런데 **근거없음→성립이 0 이 안 된다**(272~340). 남은 전환은 **전부 UNK-07 한 구간**(정상 지하철 + 미수집 버스 환승)이다. "하나라도 소스가 없으면 근거없음"은 코드로 한 줄인데, 모델은 결측 특징(`cov_any_missing=1`)을 줘도 "지하철이 정상이면 성립"과 조합을 못 가른다. 소스 존재 특징을 넣은 EXP-09 가 오히려 전환이 늘었다(272 → 338).
- 반대편 오판도 있다 — `BUS-07`(심야버스, 정상 구간) 탐침 320건을 근거없음으로 낸다. 결측이 아닌데 "버스면 모른다"로 기울었다.
- 격자탐색은 정확도 +0.01 · 전환 −65. 구조 칸(근거 등급 없음 · §3-4)은 안 바뀐다.
- 회귀 85건은 71 → 73. 틀린 12건은 여전히 무정차·운행중단·버퍼·환승 상한·배차 공백·없는 역 — 전부 시간표를 봐야 아는 자리.

**결정 — 유지.** 되돌리는 조건(§4 · 근거없음→성립 0 · 근거 등급 산출)은 v2 로도 미충족. 판정 경로 ML 미채택. 산출물: `data/travel/processed/mobility/ml_compare_v2/{report.md, summary.json, model_hgb_v2.pkl}` (특징 33 · 탐침 11,656 학습본, 1.6 MB).
**확인 안 한 것**: 더 큰 DL · UNK-07 류 혼합 구간을 씨앗에 더 넣어 외우게 하는 실험(외우게 해서 0 이 돼도 §3-2 대조군 논리대로 새 조합에선 다시 뚫린다) · 슬롯 2.

## 6. 슬롯 2 — 설계만, 미실행

**시간표 없는 버스 구간의 소요시간 추정.** 지금은 노선 유형 통계 프록시(`MOB_W_BUS_SPEED_PROXY_*`)를 쓰고,
`BUS-11`(01A 남산)에서 실측 대비 **-28%** 어긋나 도착을 아예 안 낸다. **여기가 ML 이 이길 수 있는 유일한 자리**다.

| | A 현행 | C ML(회귀) |
|---|---|---|
| 방식 | 노선 유형별 통계 | 정류장 거리·시간대·요일·노선유형 → 소요분 |
| 기준선 | BUS-11 -28% | MAE 로 재서 채움 |
| 정답 | 시간표 있는 버스 구간의 실제 소요시간을 holdout 으로 | 같은 holdout |
| 분할 | — | 구간 단위 · 시간표 도착시각은 특징에 넣지 않음 |

**오늘 안 한 이유**: holdout(시간표 있는 버스 구간 골라내기)을 만드는 데 시간이 든다.
**하게 되면**: 이기면 **추정 층에 한해** 채택 검토(판정 층은 그대로). 지면 "추정 층에도 필요 없다". 어느 쪽이든 결론이 선다.
**일정**: 4W(9/18~9/28) 후보. RAG 비교(`2026-09-11_이동모듈_RAG_비교설계_v1.md`, 경로 B)와 같은 harness 에 경로 C 로 얹는다.

## 8. 이 실험에서 배운 것

1. **쉬운 질문의 정확도는 값어치가 아니다.** 지하철 탐침 99% 는 "낮에는 열차가 있다"를 배운 것이다. 값어치는 회귀 14건이 있는 경계에 있다.
2. **「모른다」는 특징에서 안 나온다.** 소스가 없다는 사실을 봐야 나온다. 분류기는 구조적으로 확정답을 낸다 — 376/376.
3. **외워도 안 된다.** 구간을 학습에서 봤어도 근거없음→성립 38건. 정확도가 높은 모델이 더 자주 바꾼다.
4. **ML 의 자리는 판정이 아니라 추정이다.** 기준선이 -28% 로 나쁜 자리(버스 소요시간)만 후보다.
5. **"안 해 봤다"보다 "해 봤더니 이랬다"가 싸다.** 설계 반나절 · 학습 2초.
6. **한계는 실험으로 되묻는다(v2).** 구멍을 아홉 개 주면 「모른다」는 배운다(재현율 0.70). 그래도 "하나라도 없으면 모른다"는 조합은 못 배운다 — 코드 한 줄이 이긴다.
