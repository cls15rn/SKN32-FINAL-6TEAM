# Activity 실패·예외 코드와 로그를 넣었다

결론: 정상 응답으로 끝나는 실패(휴무·재난·장소 모름 등)와 도구 예외에 코드를 붙이고 한 줄 JSON 로그로 남기게 했다. 새 로그 시스템은 만들지 않고 저장소 관례(`logging.getLogger`)를 따랐다. travel·계약·DB 통합 시험 1,337건이 통과했다(61건 건너뜀, 실패 0).

## 1. 작업 목표

- 계획: `wiki/teams/activity.md` 「실패·예외 코드와 로그」(이번에 추가). 남은 작업 중 「예외 케이스 시험 + 에러 코드 로그」(휴무·장소 없음·API 실패·분류 실패).
- 선례로 이동팀 `mobility/engine/judgment_log.py` 를 읽었다. 그쪽은 이동 계산 전용(차단 목록·기기 표식·덤프)이라 그대로 쓰지 않고, 핵심(한 줄 JSON·좌표/개인정보 안 남김·로거가 본 흐름을 바꾸지 않음)만 따랐다.
- 읽어 보니 사람에게 넘기는 실패와 분류 실패는 코어가 이미 `failure_code` 와 함께 이벤트로 남긴다(`controller.py:505` `GUARDRAIL_ESCALATED`, `classification.py:77`). 그래서 **분류 실패는 다루지 않았고**, 코어가 못 보는 쪽만 맡았다.

## 2. 수행 내용

- `app/modules/travel_ops/activity/failure_codes.py`(신규) — 코드 12개와 설명, 로거 이름.
- `app/modules/travel_ops/activity/team.py` — `_record_failure`(한 줄 JSON 로그), `_read` 재정의(도구 예외를 `tool_error` 로 남기고 **다시 던짐**), `check_feasible` 의 실패 경로에 `decisions[].failure_code`, 대체 장소·일정 제출 실패 로그.
- `tests/unit/travel/test_activity_failure_codes.py`(신규, 12건).
- `wiki/teams/activity.md` — 절 추가.

정하지 않고 판단한 점:

- 대체 장소 실패는 결과의 `alternatives` 모양(`status`·`reason`)을 팀원 시험이 그대로 비교하므로 바꾸지 않고 **로그에만** 남겼다.
- 로그 저장 위치는 정하지 않았다(RULE §3.1 하드코딩 금지). logging 설정이 없으면 파이썬 기본 동작대로 표준 오류에 한 줄씩 찍힌다.
- 위급재난과 휴무가 겹치면 `failure_code` 는 위급재난이다(대체 장소 `withheld` 와 같은 우선순위).

## 4. 미해결·다음 작업

- 로그를 파일(JSONL)로 쌓으려면 운영 logging 설정이 필요하다 — 아직 없다. 어디에 쌓을지는 정해지지 않았다.
- `_unknown`(사람에게 넘김)은 코어가 기록하므로 여기서는 로그를 더하지 않았다. 코어 기록이 충분한지는 확인하지 않았다.
- 남은 작업: 이름으로 DB 조회, 카카오 존재 확인 → 「없음」 반환 흐름(④⑤), 결과 JSON 모양 정리.
