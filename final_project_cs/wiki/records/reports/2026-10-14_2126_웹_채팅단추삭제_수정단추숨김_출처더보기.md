## 1. 결론

- **채팅 아이콘 단추 삭제**: 시트 머리(일차 칩 오른쪽)의 💬 단추를 뺐다. 채팅 칸은 지금 있는 길 — 오른쪽 아래 채팅 단추 · 옆으로 밀기 — 로 들어가고, 일차 칩으로 일정 칸에 돌아온다. 채팅 칸의 이름은 그 단추를 가리키던 `aria-labelledby` 대신 `aria-label` 「채팅」.
- **채팅 칸 뒤로가기**: `[2026-10-14 사용자 지시]` 채팅 칸에 있을 때만 입력 막대 왼쪽에 회색 둥근 ← 「일정으로 돌아가기」(일정 칸에서 막대를 열었을 때의 ✕ 와 같은 자리 · 모양). 누르면 일정 칸으로 돌아가고, 쓰던 글이 없으면 막대가 접혀 오른쪽 아래 둥근 채팅 단추가 되며 포커스도 그리로 간다(쓰던 글이 있으면 막대는 ✕ 와 함께 열린 채 — 원래 동작).
- **채팅 입력칸 안내 문구**: `[2026-10-14 사용자 지시]` 고른 일정이 있으면 「{장소 이름}에 대해 궁금한 점을 입력하세요」(채팅이 고른 일정에 대해 답하므로), 없으면 지금처럼 「일정에 대해 궁금한 점을 입력하세요」. 장소 이름은 서버의 `items[].place`, 없으면 카드의 일정 이름(지도 앱 단추와 같은 기준).
- **채팅 입력칸이 여러 줄로 자람**: `[2026-10-14 사용자 지시]` 긴 글이 옆으로만 밀려 읽기 어렵던 한 줄 입력칸(`input`)을 여러 줄 입력칸(`textarea`)으로 바꿨다. 너비는 양쪽 단추 사이로 고정, 줄이 바뀌면 높이가 늘어 1줄 44px → 2줄 66px → 3줄 88px, 그 뒤는 88px 에 고정되고 입력칸 안에 스크롤바. 양쪽 단추는 맨 아랫줄에 남고, 한 줄일 때 막대는 전과 같은 58px. PC 에서는 Enter 가 전처럼 보내기 · Shift+Enter 는 줄바꿈이고, 한글 글자를 조합하는 중에 브라우저가 알리는 Enter 는 보내기로 받지 않는다(크롬은 조합이 끝날 때 Enter 를 한 번 더 알린다 — 둘 다 받으면 마지막 글자가 한 번 더 보내진다). `[2026-10-14 사용자 지시]` **휴대폰(마우스 없음 · 손가락 — `(hover: none) and (pointer: coarse)`)에서는 Enter 가 늘 줄바꿈**이고 보내기는 전송 단추로만(휴대폰 키보드에는 Shift+Enter 가 없다). 안내 문구: textarea 의 자체 문구에는 「…」가 붙지 않아(크롬 확인) 보이는 문구를 입력칸 위에 겹친 글자로 그리고 넘치면 「…」, 자체 문구는 투명한 한 줄로 남겨 화면 읽기 · 시험이 읽는다 — 자체 문구가 접히면 빈 입력칸이 두 줄로 자라던 것도 이것으로 막았다.
- **채팅 막대 펼침 모션 · 포커스 링**(2026-10-15 이어서): `[사용자 결정 — 위젯 샘플에서 B 스프링 + C 단추가 전송 단추로 · 튕김 「보통」 · 이어지는 효과 없음 · 링 4px]` 둥근 채팅 단추를 누르면 막대가 0.55초 동안 살짝 지나쳤다 돌아오며 펼쳐지고(접을 때는 전처럼 0.3초), 둥근 단추가 그 자리의 전송 단추가 된다 — 전송 단추가 58px 에서 44px 로 줄며 💬 가 ➤ 로 돌아 바뀐다(두 단추의 중심이 같은 자리). ✕ · ← 와 입력칸은 0.2초 뒤에 나타난다. 포커스 링 3px → **4px**. 입력칸 안쪽의 사각 포커스 상자(globals.css 공통 `textarea:focus-visible`)는 막대의 강조와 겹쳐 채팅 입력칸에서만 뺐다. 동작 줄이기 설정이면 모션을 모두 끈다. 샘플로 본 포커스 효과 여덟 가지(물결 · 빛 번짐 · 도는 빛 …)는 넣지 않았다.
- **「일정 수정」(✎) 단추도 스크롤 중 숨김**: 오른쪽 단추 묶음(✎ · 재난 정지 때의 「일정 정지 중」)이 일차 칩과 **같은 장치로 함께** 숨고 함께 돌아온다 — 목록을 스크롤 · 끌기 시작하면 0.15초에 걸쳐 사라지고(위로 4px), 멈추고 0.8초 뒤 0.2초에 걸쳐 나타난다. 목록 맨 위에서는 숨지 않는다. 숨은 동안은 누를 수 없고 화면 읽기에서도 빠진다(칩과 같다). ✎ 를 누르는 것은 칩을 누르는 것과 같아 단추를 숨기지 않는다.
- **목록 끝 출처**: `[2026-10-14 사용자 지시]` 「예약 표시는 입력한 정보 기준입니다.」는 **가운데 한 줄로 늘 보이고**, 그 아래 출처는 계획 확인 화면과 같은 접힌 한 줄 「ⓒ한국관광공사 · © OpenStreetMap ⌄」(OpenStreetMap 은 경로선이 그려진 날만). 누르면 상자 안에 장소 정보 출처 · 저작권 정책 링크 · 경로선 출처 · 경로 안내. 지도 위 「© OpenStreetMap contributors」 표시는 그대로다.

로컬 실서버에서 확인한 것:
- 시트 머리 오른쪽 = ✎ 하나(💬 없음), 채팅 칸 이름 「채팅」.
- 목록을 스크롤하고 0.3초 뒤: 칩 · 단추 묶음 모두 `data-quiet` · 투명 · 조작 잠김 → 1.5초 뒤 둘 다 돌아옴. ✎ 를 누르는 동작(pointerdown)은 숨기지 않고, 목록 카드를 끌면 숨긴다. 사용자도 화면에서 숨는 것을 확인했다(2026-10-14).
- 채팅 막대: 일정 칸에서 열면 ✕ 만(← 없음) → 입력칸을 눌러 채팅 칸에 들어가면 ← 만(✕ 없음) → ← 를 누르면 일정 칸 · 막대 접힘 · 포커스가 둥근 채팅 단추.
- 입력칸 안내: 고른 것 없음 = 「일정에 대해 궁금한 점을 입력하세요」, 「점심 · 광장시장」 카드를 고르면 = 「광장시장에 대해 궁금한 점을 입력하세요」. 폰 폭에서는 문구 끝이 잘린다(원래 문구도 「…입력하세」에서 잘리던 폭 — 장소 이름이 길면 더 잘린다).
- 입력칸 높이(375px 폭): 빈 칸 44px(막대 58px) → 22자 66px → 47자 88px(막대 101px) → 111자 88px 고정 · 스크롤(내용 176px). PC: Shift+Enter = 줄바꿈 · 보내기 0회, Enter = 보내기 1회(시험에서는 가로채 실제로 보내지 않음) · 줄바꿈 없음. 휴대폰 폭 터치 흉내(375px): Enter = 줄바꿈(「첫 줄
둘째 줄」 · 66px) · 보내기 0회. 안내 문구 375px = 「일정에 대해 궁금한 점을 입…」. **한글 조합 중 Enter 는 화면에서 시험하지 못했다**(내장 브라우저가 한글 조합을 흉내 내지 못함 — 사용자 PC 에서 「안녕」+Enter 한 번 = 한 번 보내기인지 확인 필요).
- 펼침 모션(375px, 2026-10-15): 둥근 단추 58px · 중심 (328, 761) → 0.03초 막대 67px · 전송 단추 58px → 0.12초 226px · 50px → 0.25초 339px · 44px · ✕ 투명도 0.18 → 0.40초 **356px(17px 지나침)** · 43px · ✕ 1 → 0.56초 이후 339px · 44px. 전송 단추 중심은 내내 (329, 761). 포커스: 막대 그림자 `0 0 0 4px` · 입력칸 `outline: none`.
- 목록 끝: 「예약 표시는 입력한 정보 기준입니다.」 가운데 정렬 · 그 아래 「ⓒ한국관광공사 · © OpenStreetMap」 접힘 → 누르면 장소 정보 출처 · 저작권 정책 · 경로선 출처 · 경로 안내 3줄.
