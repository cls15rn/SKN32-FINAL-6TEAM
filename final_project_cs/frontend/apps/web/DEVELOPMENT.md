# 웹 MVP 1차 개발 기준

작성일: 2026-09-21. 최초 범위는 로그인·회원가입·서비스 결제 없는 5개 화면이었다. 현재는 소개·온보딩·계획 읽기 확인·여행 목록·마이페이지까지 확장됐다. 이번 문서는 실제 프론트 구현 기준이며, 전체 앱·웹 확장 기획을 대체하지 않는다.

수정일: 2026-09-24. 사용자 지시로 2026-09-23 목업 [`tripilot-intro-animated-nav-switch.html`](mockups/tripilot-intro-animated-nav-switch.html)을 기준선으로 전환했다. 소개·온보딩(약관·여행 취향) 화면과 한/영 전환, 설정 사이드바를 더했고 5개 화면의 디자인을 목업에 맞췄다. 이후 화면 변경은 이 앱에서 한다. 기준선 파일은 원본(11MB)의 내장 이미지를 같은 폴더의 이미지 파일 참조로 바꾼 사본이며 내용은 같다.

목업 위치(2026-09-29): 디자인 기준선과 기존 HTML 시연 파일·공통 리소스 31개는 [`mockups/`](mockups/README.md)에 함께 보존한다. 실행 방법과 과거 목업 검증 기록은 [목업 안내](mockups/README.md)를 따른다. 현재 앱 코드와 `public/images/`의 리소스는 그대로다.

최신 확인: 2026-09-29 · `develop` `fc1ac0a`. 아래 현재 기준은 코드와 대조했고, 뒤의 날짜별 검증 기록은 당시 결과를 보존한다. 화면별 API 협의와 연결 상태는 [공유 연동 문서](../../../wiki/external/web-screen-api.md)를 따른다.

## 기술스택

Next.js 16 App Router + React 19 + TypeScript strict. Node.js 22와 npm을 사용하고 정확한 의존성은 `package-lock.json`으로 고정한다. CSS Modules와 공통 디자인 토큰으로 기존 목업의 색상·간격·배치를 유지한다. TanStack Query가 비동기 여행 데이터·캐시·진행 조회를 소유하고, Zod가 어댑터 데이터와 입력을 검증한다. 로컬 탭·선택·입력 상태는 React로 관리한다. 한 개 입력창을 위해 추가 폼/전역 상태 라이브러리를 도입하지 않는다.

공식 참고: [Next.js 설치](https://nextjs.org/docs/app/getting-started/installation), [TanStack Query 설치](https://tanstack.com/query/latest/docs/framework/react/installation).

## 화면과 개발 순서

1. 공통 레이아웃·버튼·입력·상태 표시와 여행 데이터 계약을 먼저 정의한다.
2. `/`: 소개 3장(스크롤 스냅·등장 모션). 넓은 화면에서는 402px 기기 틀, 720px 이하에서는 전체 화면. 첫 장에는 언어 선택 카드(누르면 아래로 펼쳐지고, 고르면 접힌다)와 최근 여행 3개까지의 내 여행 카드가 있고 하단에는 아래로 가는 안내만 둔다. 둘째 장은 이용 방법 4단계를 앱 화면 캡처와 함께 옆으로 넘기는 카드다.
3. `/start`: 온보딩. 맨 위 선택 입력 `디스코드 알림` 카드(웹훅만 — 복구용 이메일은 2026-10-03 에 뺐다. 번호 없음, 다른 단계의 조건이 아니다) 아래로 약관·취향 카드. 약관은 끝까지 읽어야 동의할 수 있고, 여행 취향은 설문 안내 카드 뒤에 백엔드 설문(D-020)을 따른 6문항(우선순위는 분야·세부를 누른 순서로 매기는 한 카드)을 좌우로 넘기는 카드다. 답은 여행을 등록할 때 함께 보낸다.
4. `/trips/new`: 텍스트 입력·초안 보존·예시 계획·취향 표시. 글·파일 최대 5개를 접수한다. `/intakes/[intakeId]`에서 읽는 과정과 장소·운영시간·이동 검사를 보고, 항목 잠금·삭제·장소 바꾸기·시각 고치기, 전체 자동 추천·재검증, 여행 등록을 수행한다(`README.md` 의 확인 화면 절). 일정 짜기는 `/trips/new` 의 세 번째 칸 「계획 짜 주기 (테스트)」가 한다(아래 2026-10-03 마지막 절).
5. `/trips/[tripId]/verification`: `[2026-10-03]` 따로 보는 검증 단계는 없다 — 서버가 등록할 때 판정하고, 그 확인은 `/intakes/[intakeId]`가 맡는다. 옛 주소는 그 여행 화면으로 보낸다.
6. `/trips/[tripId]/results`: 위와 같이 그 여행 화면으로 보낸다(별도 결과 통계를 만들지 않는다).
7. `/trips/[tripId]`: `[2026-10-07]` 목업 C안 — 지도 위 시트에 하루씩 일정 · 이동 줄, 시트 머리 「일정 | 채팅」, 아래 채팅 막대, 종(알림 칸), 메뉴 서랍의 항로 지킴이(아래 「2026-10-07」 절). 전에는 일정 · 지도 · 채팅을 한 칸씩 고정 하단 탭 또는 플로팅 버튼으로 바꿨다.
8. `/trips`: 여행 목록과 개별·선택 삭제(서버 `POST /v1/web/trips/{id}/delete` 에 연결 — 서버에 아직 없어 「지원하지 않아요」라고 말한다). `/mypage`·`/mypage/edit`: 사용자 키 표시, live 키 가져오기·재발급, 닉네임·이메일 입력 검증. 프로필 저장·이미지 변경은 비활성이다.

디자인 출처는 [2026-09-23 목업](mockups/tripilot-intro-animated-nav-switch.html)이다. 목업의 내비게이션 비교 스위치 대신 오른쪽 위 메뉴(프로필·여행 목록 보기·여행 취향 설문·언어·테마·애니메이션 건너뛰기·데스크탑 화면으로 보기) 사이드바에서 언어와 테마(2026-10-03부터)를 고른다. 여행 화면 내비게이션(고정 하단 탭 · 플로팅 버튼) 스위치는 2026-10-07에 뺐다. 목업은 실제 지도 대신 방문 순서 개념도를 보이지만, 앱은 지도 제공자 설정을 유지하고 `demo`일 때 개념도를 보인다. 이전 디자인 출처(A-COP `8ed3548`의 `tripilot-intake-wireframe.html`)와 기존 HTML 시연 파일은 보존한다. 상태 오류·실패·없는 여행 안내는 각 화면 내부 상태로 처리한다.

## 코드 경계

- `src/app`: URL·공통 레이아웃·페이지 조합.
- `src/components/ui`, `src/components/layout`: 실제로 재사용되는 UI. `ui`에는 공통 프로필 이미지(`Avatar`), 홈·메뉴가 함께 쓰는 언어 카드(`language-picker`), 메뉴의 테마 카드(`theme-picker`)가, `layout`에는 기기 틀·여정 틀·풍경 배경·메뉴 사이드바가 있다.
- `src/features/intro`, `src/features/onboarding`: 소개 화면과 약관·취향 온보딩.
- `src/lib/i18n.ts`, `src/lib/settings.ts`: 한/영 문구 함수와 언어·테마·애니메이션·데스크탑 화면 설정.
- `src/lib/theme.ts`, `src/styles/tokens.css`: 테마 이름과 첫 화면을 그리기 전에 저장된 테마를 거는 스크립트, 두 테마의 색 역할 변수. 화면 CSS에는 색을 직접 적지 않는다(`src/styles/tokens.test.ts`가 검사).
- `src/lib/profile.ts`, `src/features/profile`: 메뉴·마이페이지가 읽는 사용자 정보와 마이페이지 조회·수정 화면. 연동 상태는 [사용자 정보 연동 대기 항목](PROFILE_CONTRACT.md).
- `src/features/trip-registration`, `src/features/intake-review`: 등록 입력·초안과 live 접수 확인/편집/등록.
- `src/features/account`, `src/features/human-check`: 로그인 상태 카드(게스트·회원, 로그아웃)·소셜 계정 연결과 선택적 Turnstile 확인. `[2026-10-04]` 사용자 키 안내·관리 화면은 걷었다(쿠키 세션). 대신 회원용 「에이전트 연결」 카드(`agent-keys.tsx`)가 있다.
- `src/features/trip`: 여행 화면(`trip-screen.tsx` — 지도 위 시트 · 일정/이동 줄 · 채팅 · 알림 칸)·목록·삭제·화면용 타입·공통 조회·live 제안/알림/이력.
- `src/features/map`: 공통 지도 표시 계약·지도 선택·네이버/Google 지도 컴포넌트.
- `src/lib/gateway.ts`, `src/lib/live`: 연결 선택(`NEXT_PUBLIC_DATA_MODE=live` 하나 — 아니면 `components/server-not-connected.tsx` 한 화면), 실제 사용자 키·접수·여행·상담·제안/알림·삭제 연결. `[2026-10-03]` 데모 어댑터(`lib/demo`)는 없앴다.
- `src/styles`: 색상·서체와 공통 토큰.

여행 목록·조회·대화는 `TripGateway`, live 접수·확인·계획 생성·제안/알림은 `lib/live`의 별도 함수로 요청한다. 여행 캐시는 ID·화면 언어별로 나눈다. 서버 문장·오류를 자동 번역하지 않는다. 선택 언어는 현재 접수 요청에 전달하지 않으며 서버의 접수 조립·계획 생성은 `locale="ko"`다.

언어(기본 한국어 — 2026-10-03 사용자 결정, 앞서는 English)·내비게이션(기본 fixed)은 `localStorage`의 `tripilot.web.settings.v1`에 보관한다. 등록 글 초안과 대화 표시 이력은 `sessionStorage`를 사용한다. `[2026-10-04]` 사용자 키는 브라우저가 더는 두지 않는다 — 서버의 HttpOnly 쿠키 세션이고, 쓰기에 붙는 보안 토큰(`X-CSRF-Token`)은 페이지 메모리에만 있다. 옛 버전이 `localStorage` 에 남긴 키는 처음 열 때 세션으로 옮기고 지운다. 온보딩 답·약관 동의·복구 이메일 초안은 페이지 메모리에만 있어 새로고침하면 사라진다. 완료한 설문은 demo `createTrip`에서 검사하고, live `/confirm`·`/plan`에서 서버로 보낸다([설문 대응](PREFERENCES_CONTRACT.md)). 이메일 초안은 보내지 않는다.

## 실제 연동 경계

`NEXT_PUBLIC_DATA_MODE=live`는 `NEXT_PUBLIC_API_BASE`의 `/v1/web/*`에 연결한다. 쿠키 세션(게스트 시작·로그아웃·옛 키 이전), 글/파일 접수·근거 확인·편집·확인 등록/일정 생성, 여행 목록·조회·상담·제안 선택·알림을 구현했다. 서버 기준은 `app/domains/travel_ops/entry/trip_api.py`이며 UI에서 예약 변경·업무 판정·실제 시간 계산을 대신 구현하지 않는다. 실패를 데모 성공으로 바꾸지 않는다.

`Trip`·`TripStop`은 프론트 표시 모델이다. live 어댑터가 서버 `trip_id/items`를 변환하고 서울 시각으로 표시한다. 별도 검증 퍼센트 API는 없다. 접수 읽기만 서버 실시간 진행(SSE, `GET /v1/web/trip-intakes/{id}/events`)을 구독하고(안 열리면 폴링으로 되돌아감), 여행 화면의 변경 알림은 `GET …/trips/{id}/events` 종을 따로 듣는다. live 등록 시 서버가 판정하며 이후 살펴볼 점·알림·이력은 여행 화면에서 확인한다. demo 진행 조회와 가짜 서버 시험을 실제 운영 검증으로 해석하지 않는다.

미연결: 서버에 없는 여행 삭제(웹은 요청 모양대로 연결해 두었다 — [백엔드 요청](../../../wiki/records/plans/2026-10-03_1920_웹_실서버_전환_백엔드_요청.md)), 닉네임 저장·이미지 변경, 선택 언어 전달. 토큰 가져오기·재발급은 연결돼 있다. `POST /v1/web/warmup`은 `fc1ac0a`에서 서버 경로가 추가됐다. 호출 연결과 실제 모델 예열·실패 안내 검증을 구분한다. 상세 실행 조건과 제한은 [README](README.md)를 따른다.

지도 제공자 설정은 데이터 모드와 독립적이다. 유효 좌표와 웹용 키가 있을 때 실제 지도 바탕·핀을 표시하며 길찾기 선·현재 위치는 구현하지 않았다. 서버 좌표 변환과 기존 후속 제안은 [지도 문서](MAP_INTEGRATION.md)에 구분했다. 이번 문서 개정에서 외부 지도 인증이나 운영 API를 재검증하지 않았다.

## 완료 기준

기본 품질 확인은 `npm run check`(lint·typecheck·단위 검사·빌드), 브라우저 흐름과 요청/실패 처리는 `npm run test:live`(테스트용 모방 서버, 실제 서버 아님)로 확인한다. `[2026-10-03]` 데모 빌드 시험(`test:e2e`)은 없앴다. `tests/contract/test_web_client_contract.py`는 실제 서버 라우트와 설문 계약을 정적으로 대조한다. `test:real`은 실제 데이터 생성·외부 호출·팀 알림 부작용이 있는 별도 검증이므로 원본 문서 정리에서 실행하지 않는다.

주요 확인 대상은 [현재 화면 목록](README.md)의 소개·온보딩 6문항 및 완료 카드·접수 확인·여행·목록·프로필과 모드별 제한이다. API 연결 코드 존재와 운영 종단 검증 성공은 별도로 기록한다.

이하 날짜별 기록은 해당 작업 당시의 범위·실행 결과다. 옛 「미구현」「미검증」과 테스트 수치를 현재 상태나 이번 재실행 결과로 읽지 않는다.

## 1차 구현 검증 기록

2026-09-21 기준 5/5 화면을 구현했다. 린트·TypeScript 검사·프로덕션 빌드가 통과했고 Vitest 단위 테스트 21/21, Chrome에서 프로덕션 빌드를 실행한 Playwright 시나리오 8/8이 통과했다. 브라우저 검증에는 PC 1440px과 모바일 375px·320px, 지도에서 선택한 일정으로 이동·포커스, 키보드 일차 전환, 저장 실패 후 메시지 재전송을 포함한다. 밝은 화면·어두운 화면의 실제 렌더링도 확인했다. 실제 API 통합과 배포 검증은 포함하지 않는다.

같은 날 지도 모듈 추가 후 단위 검사 40/40(100%), 네이버·Google SDK 대역 브라우저 검사 6/6(100%), 기존 화면 회귀 검사 8/8(100%)가 통과했다. 지도 제공자별 빌드와 기본 데모 빌드도 통과했다. 지도 어댑터는 키 설정 후 사용하며, 실제 계정 인증·지도 타일 검증은 아직 수행하지 않았다. 실행 방법과 검증 경계는 [지도 연동 문서](MAP_INTEGRATION.md)에 기록했다.

## 취향 카드 건너뛰기·다음 버튼 기록

2026-09-28. 사용자 지시(TeamFlow `ST4F-154`)로 여행 취향 9문항의 모든 카드에 `응답하지 않고 넘어가기`를 두고, 건너뛴 질문도 진행 게이지(`00 / 9`)에 센다. 건너뛰면 그 질문의 답을 비우고 `Answers.skipped`에 질문 번호를 남긴다. 그 카드에서 다시 답을 고르면 건너뜀 표시를 거둔다. `다음`(마지막 카드는 `설정 완료`)은 모든 카드에서 선택지를 골라야 켜진다 — 기피 음식·종교 카드도 이제 `해당 없음`·`없음`·`응답하지 않음` 같은 선택이 필요하다. 좌우로 밀기·방향키로 앞으로 넘기는 것도 같은 기준을 따르며, 선택 없이 넘어가는 길은 건너뛰기 버튼뿐이다. 건너뛴 테마·인원은 완료 요약에 `미선택`으로 보이고, 등록 화면은 인원 표시를 뺀다. 모든 질문을 건너뛸 수 있게 되어, 기피 음식·종교 카드 설명 옆에만 있던 `선택` 표시는 사용자 지시로 모든 카드에서 뺐다.

검증: 린트·TypeScript 검사·프로덕션 빌드 통과. Vitest 단위 테스트 49/49(100%). ## 취향 설문 안내 카드·답변 전송 기록

2026-09-28. 사용자 지시(TeamFlow `ST4F-155`).

## 내 여행 목록 기록

2026-09-28. 사용자 지시로 `/trips`에 내 여행 목록을 더하고, 같은 날 사용자가 준 요구사항에 따라 첫 화면·메뉴·헤더를 목록으로 들어가는 흐름에 맞춰 정리했다.

- 첫 화면 카드: 소개 첫 장의 언어 카드 아래에 `내 여행` 카드(`RecentTrips`)를 두고 최근 등록 3개까지 보인다. 1~2개면 그 수만, 없으면 `아직 등록한 여행이 없어요.`만 보인다(빈 줄·등록 버튼 없음). 4개 이상일 때만 오른쪽 위에 `전체일정 보기`가 생겨 `/trips`로 간다. 불러오는 중·빈 목록·실패를 카드 안에서 따로 보이고, 실패는 오류 문장과 `다시 불러오기`로 알린다 — 소개 화면 전체를 오류 화면으로 바꾸지 않고, 빈 목록으로 숨기지도 않는다.
- 첫 장 하단: 아래로 가는 안내·버튼만 둔다. `소개 건너뛰기`는 첫 장에서 뺐고 둘째 장에는 그대로 있다. 셋째 장의 `내 일정 시작하기`는 `[2026-10-06 사용자 지시]` 이제 항상 계획 올리는 화면(`/trips/new`)으로 간다(약관에 동의하지 않았으면 `ConsentGate` 가 약관 화면으로 보내고, 처음 동의하면 취향 설문 없이 바로 계획 화면으로 간다. 취향 설문은 메뉴의 `여행 취향 설문` 줄이나 마이페이지에서 따로 연다).
- 첫 장 높이: 카드가 들어가도록 언어 카드 위아래 여백(22·14 → 16·10px)과 배지 아래 여백(10 → 6px)을 줄이고, 카드 줄은 46px(터치 44px 이상)로 촘촘하게 했다. 여행 3개일 때 한국어 375×812·390×844·PC 기기 틀(1280×900)에서 첫 장이 넘치지 않는다(각 812/812·844/844·851/851px). 영어 375×812는 제목이 세 줄이라 22px 넘치지만 넘친 부분은 점 내비게이션용 아래 여백이고, 소개와 3개는 한 화면에 보인다. 더 낮은 화면은 내용을 자르지 않고 첫 장 안에서 스크롤된다(목록 안의 별도 스크롤은 없다).
- 메뉴: 오른쪽 위 설정 사이드바를 `메뉴`로 바꾸고(버튼·제목·닫기 이름 포함) 맨 위에 `여행 목록 보기 →`(→ `/trips`, 여행 수와 무관하게 항상)를 두었다. 누르면 메뉴를 닫고 이동하며, 이미 목록 페이지면 닫기만 한다. 링크도 Tab 포커스 순환에 들어가고, Esc로 닫으면 메뉴 버튼으로 포커스가 돌아온다. 언어·여행 화면 내비게이션 설정은 그대로다. 소개·온보딩(기기 틀)과 여정 화면(여정 틀)이 같은 메뉴를 쓴다.
- 헤더: 여정 화면 헤더에는 왼쪽 로고와 오른쪽 메뉴만 둔다(가방·집 버튼을 뺐다). 로고는 모든 화면에서 `/`의 첫 장으로 가고, 소개 화면 안에서는 첫 장으로 스크롤한다. 등록 화면 아래의 `/start` 링크는 단계 이동이라 `홈으로`에서 `이전`으로 이름을 바꿨다(가는 곳은 같다). `/trips`와 그 안의 `새 여행 등록`은 그대로다.
- 한 줄: 제목과 등록 시각(서울 시각)을 보인다. 서버 목록(`GET /v1/web/trips`)이 주는 값이 제목·일정 판·등록 시각뿐이라, 기획서 U02의 여행 날짜·상태·미확인 제안 수는 없다 — 목록 응답에 칸이 생기면 붙인다. 일정 판이 2 이상이면(등록 뒤 새 판이 생겼으면) `바뀐 일정 있음` 배지를 단다. 줄을 누르면 여행 화면으로 가고, 관리 시작 전이면 여행 화면이 검증·결과로 안내한다.
- 게이트웨이·캐시: `TripGateway.listTrips`를 `useTrips` 하나로 불러, 첫 화면 카드와 `/trips`가 같은 조회·정렬·캐시를 쓴다. 여행을 등록하면(데모 등록, 실제 연결의 확인·일정 짜기) 목록 캐시를 지워, 돌아왔을 때 옛 목록을 잠깐 보이지 않고 다시 읽는다. 실제 연결은 저장된 사용자 키가 없으면 서버를 부르지 않고 빈 목록을 보인다 — 부르면 빈 목록을 보이려고 새 사용자 키(서버 사용자)를 만들게 된다. 데모는 이 탭의 `sessionStorage`에서 데모 여행을 모아 최근 등록 순으로 보이고, 제목이 없어 날짜로 이름 붙인다(`2026-09-15 – 2026-09-16 여행`). 등록 시각은 저장 형식의 선택 칸 `createdAt`으로 더했고, 그 전에 저장된 데모 여행은 시각 없이 맨 아래에 온다. 읽을 수 없는 데모 여행이 하나라도 있으면 건너뛰지 않고 목록 전체가 기존 `CORRUPT_STORAGE` 오류를 보인다.

## 내 여행 개별·선택 삭제 기록

2026-09-29. 사용자 지시(TeamFlow `ST4F-163`). `/trips` 목록에서 여행을 하나씩 또는 골라서 지운다. **데모 모드만 실제로 지운다.** 서버에는 여행 삭제 호출이 없어(`trip_api.py`의 `/v1/web/trips`는 GET·POST뿐, `app/` 전체에 delete 라우트 없음) live 모드는 삭제 제어를 끄고 이유를 보인다.

- 일반 모드: 제목 줄 오른쪽 `선택 삭제`(`PageHeading`에 선택 속성 `action`을 더했다 — 다른 화면의 출력은 그대로). 행은 `제목·등록 시각 / 화살표 | 휴지통`이고, 휴지통은 링크 안이 아니라 옆의 별도 버튼이라 눌러도 여행이 열리지 않는다. 휴지통 이름에 제목과 등록 시각을 넣었고(`2026-09-15 – 2026-09-16 여행(… 등록) 삭제`), 지우는 대상은 여행 ID로 정한다 — 같은 제목의 여행이 여럿이어도 누른 행만 지운다.
- 선택 모드: `선택 삭제` → 제목 오른쪽이 `취소` · `삭제 (N)`으로 바뀌고 각 행 앞에 네이티브 체크박스가 생긴다. 아무것도 고르지 않은 채 시작하고 0개면 `삭제`가 꺼진다. 행 전체가 체크박스 라벨이라 어디를 눌러도 고르거나 풀고, 여행은 열리지 않는다. 화살표·휴지통과 `새 여행 등록`은 숨긴다. 고른 행은 체크와 옅은 배경·테두리로 보인다. 상단 `취소`는 선택을 비우고 모드를 끝낸다. 선택은 화면 상태에만 있어 다시 들어오면 비어 있다.
- 확인창(`alertdialog`, 메뉴와 같이 `document.body`에 띄움): 한 건은 `이 여행을 삭제할까요?`와 제목·등록 시각, 여러 건은 `선택한 여행 N개를 삭제할까요?`와 `N개 삭제`. 둘 다 `이 탭에 저장된 여행과 대화 기록이 삭제돼요. 삭제한 내용은 되돌릴 수 없어요.`를 적는다(데모 여행 레코드에 일정·검증·대화가 함께 들어 있어 사실과 맞다). 첫 초점은 `취소`, Tab은 두 버튼 사이에서만 돌고, Esc는 취소, 배경을 눌러도 아무 일이 없다. 확인창 `취소`는 창만 닫고 선택 모드와 체크를 지킨 채 누른 버튼으로 초점을 돌린다. 삭제 중에는 `삭제 중…`이고 두 버튼이 `aria-disabled`라 다시 눌리지 않는다. ★삭제를 누른 뒤 창은 최소 0.5초(`MIN_DELETING_MS`, Windows 기본 더블클릭 간격) 남는다 — 데모 삭제는 몇 ms 만에 끝나 더블클릭의 두 번째 클릭이 아래 여행 행에 떨어져 여행을 열던 것을 시험이 잡았다.

- **종**: 머리줄 메뉴 옆. 누르면 알림 칸이 열리고 그 안에 지금까지의 묶음(`TripAttention` — 선택 요청 · 되돌리기 · 살펴볼 점 · 받은 알림 · 변경 이력 · 여행계획서 링크)이 있다. 재난 정지 패널은 일정 칸 맨 위에 그대로 선다.
- **항로 지킴이**: 머리줄이 아니라 메뉴 서랍 머리(닫기 ✕ 왼쪽, `SettingsMenu` `tools` + `CloseMenu` 문맥). 꺼진 것을 누르면 서랍이 닫히고 카드가 묻는다 — 카드 끝 줄은 「켠 뒤에도 언제든 메뉴에서 끌 수 있어요.」(`GuardianCard` `iconIn="menu"`, 등록 전 화면은 그대로 「화면 위 아이콘에서」). 서버 호출은 그대로(`POST …/guardian`).

## 2026-10-08 (이어서) — 실서버 확인 뒤 고친 것 · 일정 카드 머리

## 2026-10-15 (이어서) — 지도 경로의 걷는 구간 = 회색 점(ST4F-495)

`[2026-10-15 사용자 결정 — B안 · 회색 점]` 웹 여행 화면 10항목 중 묶음 4. 이 가지는 `role-manager` 로 PR 한다.
- **서버가 경계를 준다**: 지하철 · 버스 이동은 선 하나에 양 끝 걸음이 이어 붙어 와서 화면은 어디까지가 걸음인지 모른다 — 경로선 응답의 새 칸 `walks`(line 좌표 번호 [처음, 끝], [계약](../../../wiki/external/rest-endpoints/web-trips.md))를 읽는다(`lib/live/route-shapes.ts` — 줄 밖 · 순서가 어긋난 번호 · 점을 버린 선이면 믿지 않는다). 칸이 없는 응답(옛 서버 · 모방 서버)은 걷기 이동만 점이다(`route-lines.ts` `walksOf`).
- **그리기**(`providers/lines.ts` `linePieces` · `walkStyle`): 한 이동의 선을 걷는 조각 · 타는 조각으로 잘라(끝점 공유 — 선이 끊기지 않는다) 걷는 조각은 도보 색(`--color-muted`) 둥근 점, 나머지는 그 이동의 모양 그대로. OSM = `dashArray "0.1 10"` + 둥근 끝, 구글 = 원 기호(`SymbolPath.CIRCLE`) 반복, 네이버 = `strokeStyle: "dot"`. 길을 몰라 이은 직선(`dashed`)은 자르지 않고 흐린 긴 점선 그대로. 누른 경로 강조는 그 이동의 조각이 함께(OSM), 누르는 투명 선은 이동마다 하나.
- **안내 문구**: 직선 추정 선과 걸음 점이 함께 있으면 「점선은 길을 몰라 …」 아래에 「동그란 점은 걷는 구간이에요.」를 더한다(기존 문장은 그대로). 지도 위 범례(`RouteTags`)는 지금 화면에 쓰이지 않아 고치지 않았다.
- 검증 · 남은 일: [리포트](../../../wiki/records/reports/2026-10-15_0206_웹_지도경로_도보구간점선.md). `check` · `test:live` 는 돌리지 않았다(PR 직전에 몰아서).
