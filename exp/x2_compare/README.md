## 정한 것 (이유)

- **비교 대상은 지하철만으로 된 케이스** — GTFS 에 버스·택시·자전거가 없다. 이슈(무정차·중단)가 붙은 케이스도 뺀다(MOTIS 에 없는 입력). 섞인 케이스 안의 지하철 구간은 구간 단위로만 댄다.
- **성립/불가는 두 쪽에 같은 조건으로** — 케이스 출발 뒤 180분 안에 떠나고 운행일(28:00) 안 · `arrive_by` 가 있으면 그 시각까지 닿아야 성립. (첫 판은 목표가 없을 때 「우리 예정 도착+1분」을 목표로 줘 우리 결과에 묶여 있었다 — GPT 대조로 고침)
- **「도착 목표 시각까지」(arriveBy)는 마지막 출발 셋에 쓴다** — L1 운행일 마지막 출발(28:00 까지 도착 · 이 GTFS 의 마지막 시각은 25:14:30 이라 잘리는 편 없음) · L2 `arrive_by` 까지 · L3 `arrive_by` − 우리 @ 까지. 우리 「늦어도 출발」과는 뜻이 같은 것끼리 댄다(목표 없으면 L1 · 있으면 L3).
- **같은 경로는 한 구간씩 넣어 잇는다** — MOTIS 자유 탐색은 도착이 같은 다른 환승역을 골라 케이스의 경로가 답에 안 나온다. `maxTransfers=0` 은 v2.11.3 에서 빈 답을 낸다 → 그 노선 정류장 id 끼리 넣고 탑승 구간이 하나인 여정만 고른다.
- **환승 시간은 MOTIS 가 쓰는 값으로** — GTFS `transfers.txt`(도보 초) 를 분으로 내리고 최소 2분(임의 400쌍 질의로 확인). 우리 판정은 도보 + 길찾기 1분을 올림 → 이 차이가 도착 어긋남의 가장 큰 원인이다(분류 ①).
- **2호선 성수 · 6호선 응암에서 같은 노선을 3분 안에 이어 탄 것은 한 구간으로 본다** — X1 의 편이 행선지가 바뀌는 역에서 끊겨 있다. 그 밖의 역에서 같은 노선끼리 갈아탄 것(구로 · 신도림 지선)은 진짜 환승이라 합치지 않는다.
- **synthetic 묶음은 실 시간표로 다시 돌린 우리 판정과 댄다** — MOTIS 는 실 시간표만 싣는다(축소 시간표 기대값과는 무관).
- **±1분은 일치** — MOTIS 응답은 분 단위(초를 내림), 우리는 올림(X1 주의 4).
- **「②MOTIS」는 원천 시간표 행에 댄 것** — 실측·공식 시간표 대조가 아니다. 둘이 같다는 것도 「맞다」가 아니다(같은 원천).

## GPT 대조 반영 (2026-10-05 · 제시 12)

- **MOTIS 쪽 상태를 가른다** — 성립 / 목표에 늦음 / 그 운행일에 편 없음(GTFS 직접 계산으로 확인) / 응답 후보에 없음(미확인) / 질의 오류. 「응답에 없다」를 「불가」로 세지 않는다.
- **고정 경로 = MOTIS 구간 탐색 + 이 스크립트의 연결기** — MOTIS 의 전체 경로 판정이 아니다. 자유 탐색(multi · 첫 쪽 6개)은 따로 센다.
- **환승 시간만 우리 값으로 맞춘 재실행**을 둔다 — 「환승모델」 분류는 여기서 사라지는 것만.
- **성수·응암 이어 타기에 기댄 줄을 따로 표로** — 같은 차량이라는 근거가 없다.
- **종착 추정을 뺀 판은 같은 케이스 교차표로** — 분모가 다른 비율을 나란히 두지 않는다.
- **이름** — 「같은 편」→「승차 시각 같음」 · 「②MOTIS」→ 원천행 / 추정연결 / 그래프 · 「n/199」→ 비교 가능 109/199 와 n/109.
- 못 한 것: 초 단위 경계 시험(MOTIS 내부가 분 단위라 직접 계산과의 차이 1건으로만 봄) · 독립 정답(공식 편별 시간표 · 실측) 대조 · 동시성·실패율·갱신 비용.
